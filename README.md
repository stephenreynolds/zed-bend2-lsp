# Bend for Zed

[Bend 2](https://github.com/bendlang/bend) support for the Zed editor.

- Syntax highlighting, bracket matching, auto-indent and outline, using the
  [tree-sitter-bend2](https://github.com/Soulthym/tree-sitter-bend2) grammar.
- The [bend2-lsp](https://github.com/IlyaGulya/bend2-lsp-rs) language server:
  diagnostics from the Bend compiler, completion with auto-import, hover,
  signature help, go to definition and type definition, find references,
  rename, document highlights, formatting, organize imports, code actions,
  inlay hints, code lenses, semantic tokens and symbol search.
- Run buttons in the gutter: `def main` runs the file, and each `law` checks
  the file's proofs.
- Snippets for definitions, datatypes, laws, matches and `do` blocks.
- Vim text objects for definitions, datatypes and comments.

This extension targets Bend 2. The original Bend (HVM2) syntax is not
supported.

## Requirements

- **Bend 2**, with `bend` on your `PATH`. The language server runs
  `bend <file> --check-only` to produce diagnostics.

  ```sh
  curl -fsSL https://bend-lang.com/install.sh | sh
  ```

- **[bend2-lsp](https://github.com/IlyaGulya/bend2-lsp-rs)**, the language
  server. You don't have to install it yourself: if it isn't on your `PATH`,
  the extension downloads it on first use (see [Language server](#language-server)).
  Without it you still get highlighting, outline, snippets and run buttons,
  but no diagnostics, completion, hover, navigation or formatting.

## Language server

The extension looks for the server in this order:

1. `lsp.bend2-lsp.binary.path` in your Zed settings.
2. `bend2-lsp` on your `PATH`.
3. A download of the pinned release (currently v0.7.1) from the server's
   GitHub releases. The file is checked against the release's published
   SHA-256 before it is run.

Prebuilt servers exist for macOS, Linux (glibc 2.39 or newer) and Windows, on
x86_64 and ARM64.

### Settings

`lsp.bend2-lsp.settings` is sent to the server unchanged. The server reads
compiler options from a `bend2-lsp` object and lint options from a `bend`
object:

```json
{
  "lsp": {
    "bend2-lsp": {
      "binary": { "path": "/absolute/path/to/bend2-lsp" },
      "settings": {
        "bend2-lsp": {
          "compilerPath": "/absolute/path/to/bend",
          "compilerArguments": []
        }
      }
    }
  }
}
```

See the [server documentation](https://github.com/IlyaGulya/bend2-lsp-rs#readme)
for the optional `bend.lint` settings.

## Editor settings

Some server features are off by default in Zed. Turn on the ones you want:

```json
{
  "code_lens": "on",
  "languages": {
    "Bend": {
      "semantic_tokens": "combined",
      "inlay_hints": { "enabled": true },
      "document_symbols": "on",
      "document_folding_ranges": "on"
    }
  }
}
```

- `semantic_tokens` lets the server color the parts of a dotted name
  separately (`IO` as a type, `print` as a function). Tree-sitter sees
  `IO.print` as a single name.
- `inlay_hints` shows argument names at call sites.
- `code_lens` shows reference counts above definitions. It is an editor-wide
  setting, so it applies to other languages too.
- `document_symbols` and `document_folding_ranges` switch the outline and
  folding from Tree-sitter to the server.

The extension sets a tab size of 2, which is what the Bend guide uses. The
server's formatter follows your tab size, so if your files use another width,
set it:

```json
{ "languages": { "Bend": { "tab_size": 4 } } }
```

To stop the server from reformatting on save, set `"format_on_save": "off"`
for `Bend`.

## Tasks

| Task | Command | Where |
| --- | --- | --- |
| Run | `bend <file>` | Run button on `def main`, or `task: spawn` |
| Check | `bend <file> --check-only` | Run button on a `law`, or `task: spawn` |
| Verdict | `bend <file> --verdict` | Run button on a `law`, or `task: spawn` |
| Build | `bend <file> -o <file without extension>` | `task: spawn` |

## Limitations

- The grammar tracks Bend 2.0.36. It parses the Bend 2.0.40 Base library and
  every program under `demos/`, `bench/` and `guide/` in the Bend repository
  without errors. A few forms in Bend's own test suite still produce error
  nodes; highlighting recovers on the next definition.
- Hover and completion come from declarations. The server does not infer the
  types of arbitrary expressions.
- The server also implements call hierarchy and type hierarchy. Whether they
  appear depends on your Zed version.

## Development

Install Rust with rustup, then run `zed: install dev extension` and choose
this directory. Zed compiles the Rust code and the grammar. Query load errors
appear in `zed: open log`.

To update the pinned server, change `SERVER_VERSION` and the checksums in
`src/lib.rs` from the new release's `SHA256SUMS`.
